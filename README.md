# RevitNumbering - нумерация элементов модели Revit

Плагин для Revit 2022, 2024 (.NET Framework 4.8) и 2025 (.NET 8). Немодальное окно показывает элементы выбранной категории - стены, двери, окна, помещения, - строит номера по шаблону и пространственному порядку и записывает их в параметр: "Марка" у стен, дверей и окон, "Номер" у помещений.

## 1. Сборка, установка, запуск

### Что нужно

- Visual Studio 2022 или новее (MSBuild) с рабочей нагрузкой "Разработка классических приложений .NET", пакет нацеливания .NET Framework 4.8.
- .NET SDK 8.
- WiX Toolset v3.11+ (для MSI).
- Доступ к nuget.org: Revit API берется пакетом `Revit_All_Main_Versions_API_x64`.

### Сборка под каждую версию

Одна кодовая база, три конфигурации решения:

| Конфигурация | Revit | Среда |
|---|---|---|
| R2022 | 2022 | net48 |
| R2024 | 2024 | net48 |
| R2025 | 2025 | net8.0-windows |

Все сразу, вместе с установщиком:

```powershell
.\build.bat
```

Одна версия:

```powershell
msbuild RevitNumbering.sln /restore /p:Configuration=R2024 /p:Platform=x64
```

Результат версии - папка `RevitStartup\bin\x64\<конфигурация>\<среда>\` (например, `RevitStartup\bin\x64\R2024\net48\`), установщик - `InstallerWIX\bin\Release\InstallerWIX.msi`.

### Тесты (без Revit)

```powershell
dotnet test RevitNumbering.Tests

dotnet test RevitNumbering.UI.Tests
```

Оба проекта выполняются на net48 и net8.0 без Revit.

### Установка

- **MSI:** запустить `InstallerWIX.msi`. Установка - для текущего пользователя. Отмечаются установленные версии Revit.

- **Манифест .addin:** `%APPDATA%\Autodesk\Revit\Addins\<версия>\`
- **DLL:** `%APPDATA%\Autodesk\Revit\Addins\<версия>\RevitNumbering\`
- **Настройки:** `%LOCALAPPDATA%\RevitNumbering\<версия>\settings.json`
- **Журнал:** `%LOCALAPPDATA%\RevitNumbering\<версия>\Logs\numbering-<дата>.log`

### Запуск

Revit → вкладка "RevitNumbering" → панель "Нумерация" → кнопка "Нумерация".

## 2. Как пользоваться

1. **Категория.** Выбрать в списке. Таблица показывает все элементы категории: ID, имя ("Семейство : Тип"), уровень, текущее значение, новое значение, статус и кнопку "Показать" (приближает элемент в Revit и выделяет его; окно сворачивается).
2. **Шаблон (правая панель).** Поля: префикс, галочка "Уровень", разделитель между уровнем и счетчиком, разрядность счетчика (1-9), суффикс; кнопка "Поменять местами" ставит счетчик перед уровнем. Под полями показан пример. Новые значения пересчитываются при вводе.
3. **Порядок нумерации.** Сетка: начальный угол, направление (рядами или столбцами), допуск ряда в мм.
4. **Охват.**
   - **Видимые в таблице.** Все строки, а при вводе в поиск - те, что остались после поиска.
   - **Выбранные в модели.** Кнопка "Выбрать в модели" запускает выбор в Revit с фильтром по категории (текущее выделение предвыбрано, группы и сборки разворачиваются в свои элементы); Esc ничего не меняет. Таблица при этом показывает все строки, а нумеруются только выбранные; если введен поиск - выбранные, подошедшие под поиск. "Сбросить выбор" возвращает к видимым строкам. Выбор запоминается отдельно для каждой категории.
   - Строка "Охват" над таблицей показывает, что в охвате и сколько элементов.
5. **Поиск (правая панель, над шаблоном).** Без учета регистра, по части текста, при каждом изменении текста. Режим "Вся таблица" ищет по ID, имени, уровню и текущему значению. Режим "Столбец" ищет по одному выбранному в списке столбцу (ID, Имя, Уровень, Текущее значение).
6. **Проверить результат до записи.** Колонка "Новое значение", строка под таблицей (сколько изменится, сколько зафиксировано, сколько занятых номеров пропущено), статусы строк.
7. **"Применить".** Запись - один шаг в журнале отмены Revit ("Нумерация элементов"). После записи открывается окно "Результат".
8. **"Отменить".** Активна только пока идет запись после "Применить". Откатывает все записанное.
9. **"Обновить".** Перечитывает модель и возвращает охват "видимые в таблице".

### Статусы строк

- **Изменится:** Новое значение отличается от текущего
- **Без изменений:** Новое значение совпало с текущим
- **Вне охвата:** Строка не в охвате, ее значение не меняется
- **Зафиксирован: причина:** Элемент в охвате, но менять его нельзя: нет уровня, нет положения в модели, занят другим пользователем, параметр только для чтения, помещение не размещено, не окружено или избыточное
- **Занимает номер:** Элемент вне охвата или зафиксированный, чей номер счетчик был вынужден пропустить

### Шаблон номера

Номер собирается так: префикс + имя уровня + разделитель + счетчик + суффикс. Если стоит "Счетчик первым", то: префикс + счетчик + разделитель + имя уровня + суффикс. Без галочки "Уровень" - префикс + счетчик + суффикс. Счетчик дополняется нулями слева до заданной разрядности. Имя уровня берется целиком. Счетчик начинается с 1 на каждом уровне.

Пример по умолчанию для дверей: `Д-` + `Этаж 1` + `-` + `001` = `Д-Этаж 1-001`.

Ошибки видны сразу под полями и блокируют "Применить":

- в охвате несколько уровней, а уровень не входит в номер;
- одинаковый номер получается на разных уровнях (например, уровень "1" со счетчиком 11 и уровень "11" со счетчиком 1 дают "111" при пустом разделителе).

Предупреждение (не блокирует): номер длиннее разрядности счетчика.

## 3. Архитектура

### Слои

```
RevitStartup ──► RevitNumbering (Revit-слой) ──► RevitNumbering.UI ──► RevitNumbering.Core
                         └────────────────────────────────────────────►┘
RevitNumbering.Tests    ──► Core
RevitNumbering.UI.Tests ──► UI, Core
```

- `RevitNumbering.Core` (netstandard2.0): Модель данных, шаблон, стратегии порядка, расчет номеров, настройки, координатор `NumberingSession`, журнал
- `RevitNumbering.UI` (WPF): Окна, модели представления, все тексты (`Texts.resx`), поиск
- `RevitNumbering` (Revit-слой): Категории, чтение, выбор и показ элементов, запись, события документов, вызыватель (`ExternalEvent`), сборка объектов
- `RevitStartup`: `IExternalApplication`, лента, манифест

### Как добавить категорию

Четыре правки, на примере категории "Мебель" (параметр "Марка"):

1. Класс в `RevitNumbering/Revit/Categories/Categories.cs`:

```csharp
public sealed class FurnitureCategory : RevitCategory
{
    public override string Key => "Furniture";

    public override BuiltInCategory Category => BuiltInCategory.OST_Furniture;

    public override BuiltInParameter NumberParameter => BuiltInParameter.ALL_MODEL_MARK;
}
```

2. Строка в списке категорий в `PluginEntry.Initialize`: `new FurnitureCategory(),`

3. Запись в `RevitNumbering.Core/Settings/defaults.json`:

```json
{
  "categoryKey": "Furniture",
  "prefix": "М-",
  "includeLevel": true,
  "levelFirst": true,
  "separator": "-",
  "width": 3,
  "suffix": "",
  "ordering": { "type": "Grid", "start": "TopLeft", "byColumns": false, "rowToleranceMm": 500 }
}
```

4. Текст в `RevitNumbering.UI/Resources/Texts.resx`: `Category_Furniture` = "Мебель".

## 4. Решения

### Порядок нумерации

При выборе порядка нумерации, в поисках альтернативы ТЗ, первой мыслью было привязывать порядок нумерации по помещениям, т.к. Окна, Двери, Стены в теории должны принадлежать однозначно какому-то помещению. От идеи быстро отказался из-за бессмысленности такой нумерации, в частности для стен, и необходимости выведения каких-то условных правил принадлежности дверей на границе помещений. Принял решения брать пример из ТЗ, вопрос выбора точки был определен самими категориями - точка вставки, при ее отсутствии середина линии, и центр bb. Если нет уровня, то элемент не нумеруется, сохраняет свое значение, получает статус - нет уровня, его номер считается занятым. Аналогично если нет точки после `GetPoint()` (содержит все 3 способа получения точки для категории), статус - нет положения в модели. Учел возможность нумерации для вложенных семейств и витражей, берется уровень основы.

Сам порядок сделал сеткой, как в ТЗ, название чуть не корректное по смыслу, но глобально столбцами\рядами, сверху вниз и слева направо, при возможности выбора противоположных направлений (в сумме 8 вариантов). Ориентация привязана к осям модели, не зависимо от активного вида.

Работа идет с координатами, которые 99% не будут лежать на одной линии. В следствии этого замечания, добавил допуск. Если координата поперек ряда отличается от координаты первого элемента ряда не больше допуска, элемент попадает в этот ряд. Ряд привязан именно к первому элементу (если предыдущий, то склеиться). Если координаты вдоль ряда различаются меньше чем на 1 мм, то смотрю по ID.

Архитектурно решил, что для каждой категории своя стратегия со своими параметрами. В рамках тестового задания и предложенных категорий это избыточно, но глобально, позволит добавить категорию Лист, и сделать для нее свою стратегию. Новый вариант стратегии добавляется отдельным классом, полиморфизм как у категорий.

В референсах, узнал про организацию порядка методом "линии" (нумеруются в порядке, в котором она проходит элементы). Добавлять не стал, отмечаю как вариант на перспективу.

### Шаблон

Сначала добавил поле ввода: тогда весь номер виден сразу как строка, как в примере из ТЗ. Но обрабатывать ошибки ввода и лишний раз давать проектировщику возможность ошибиться показалось не user-friendly, поэтому заменил на конструктор. Для полного контроля номера добавил префикс, суффикс, разделитель и возможность менять местами уровень и порядковый номер. Отдельной функцией добавил выключение уровня из номера. Не самый реалистичный сценарий, но, сделав невозможным применить нумерацию при дубликации номера, в сумме закрыл 3 цели: простота ввода данных, максимальный контроль и вариативность номера, защита от ошибочного ввода. Был еще вариант вместо имени уровня брать параметр из уровня, но посчитал его избыточным.

Отдельно добавил обработку ошибок и предупреждений с понятным пояснением и предложением решения.

Ошибки, блокируют "Применить" (видны сразу под полями шаблона):

- В охвате несколько уровней, а уровень не входит в номер: номера на разных уровнях совпадут. Предложение: включить "Уровень".
- Один и тот же номер получается на нескольких уровнях, например уровень "1" со счетчиком 11 и уровень "11" со счетчиком 1 дают "111". Предложение: добавить разделитель между уровнем и номером.

Предупреждение, не блокирует применить: номер длиннее разрядности счетчика, номера будут разной длины.

Защита ввода и элементов:

- Разрядность принимает только одну цифру от 1 до 9, вставка запрещена, при неверном значении подсказка "Введите целое число от 1 до 9".
- Элемент без уровня, когда уровень входит в номер, нумерацию не ломает: он сохраняет свое значение и получает статус "Зафиксирован: нет уровня".

### Запись

Из ТЗ для кнопки "Применить" были четыре требования:

- вся операция одним шагом в журнале отмены,
- элементы, которые нельзя изменить, не срывают остальных (в сводке что пропущено и почему),
- без серии предупреждений Revit,
- после записи таблица показывает фактические значения из модели.

Первое решение было писать каждый элемент своей транзакцией внутри группы транзакций, которая в конце закрывается через `Assimilate`: так один сбойный элемент откатывается отдельно, а вся запись остается одним шагом отмены. Понимал, что решить задачу скорости, заморозки и тормозов UI при 10000+ элементов полноценно не получится (по крайней мере я не знаю решения, и тем более делая группы транзакций по транзакции на каждый элемент). Решил хотя бы не убивать окно одним запросом, поэтому решение писать пачками кажется самым оптимальным: транзакция на пачку внутри той же группы. Если фиксация пачки не удалась, эта пачка пишется поэлементно: плохие элементы попадают в сводку с причиной, остальные записываются. Размер пачки 150 элементов, подбирал на категории стен (около 22 000 элементов) по визуальному восприятию UI и характерного фриза при каждой итерации.

Субтранзакции не рассматривал, т.к. ошибки выявились бы только после коммита родительской транзакции.

До записи проверяю элементы, которых лучше не трогать: удален, занят другим пользователем, устарел относительно хранилища, параметр только для чтения. (В ТЗ была пометка, про совместную работу). Такие элементы не пишутся и попадают в сводку с причиной.

### Конфликты при записи

Занятые номера решаются до записи, в разделе "Конфликты": номер, занятый элементом вне охвата или зафиксированным элементом, пропускается, элемент получает следующий свободный. Повторы в плагине не допустимы. При записи отдельно обрабатываются ситуации, которые могли возникнуть после предпросмотра: перед записью модель читается заново, номера пересчитываются и сравниваются с тем, что видел пользователь. Если не совпало (что-то удалили\изменили), ничего не пишется, таблица обновляется, а в статусе появляется сообщение, что данные изменились. Если конкретный элемент занят другим пользователем или устарел относительно хранилища, он не пишется и попадает в сводку с причиной, остальные записываются. Предупреждения Revit снимаются молча, а ошибка откатывает только свою транзакцию.

### Настройки

Решение хранить в `%LOCALAPPDATA%\RevitNumbering\<версия Revit>\settings.json` используется как стандартное при разработке (в моей практике). Отдельный файл на каждую версию Revit. В одной папке лежат натсройки и журнал. При крит. ошибках (который мы не предусмотрели), в окне уведомления можно скопировать журнал сразу. Поэтому проектировщику нет нужды лезть в папку, трогать как либо файлы.

Хранится: по каждой категории префикс, галочка "Уровень", порядок уровня и счетчика, разделитель, разрядность, суффикс и стратегия порядка с параметрами (угол, направление, допуск ряда);  Не хранятся поиск, охват, выбор в модели и размер окна (сеанс работы, а не настройки)

Формат: `System.Text.Json`. Имена в camelCase, перечисления строками, стратегия порядка определяется полем `"type"`. Пример записи категории:

```json
{
  "categoryKey": "Doors",
  "prefix": "Д-",
  "includeLevel": true,
  "levelFirst": true,
  "separator": "-",
  "width": 3,
  "suffix": "",
  "ordering": { "type": "Grid", "start": "TopLeft", "byColumns": false, "rowToleranceMm": 500 }
}
```

Умолчания: встроенный в плагин `defaults.json` того же формата, строгий режим. У каждой зарегистрированной категории должна быть полная верная запись, запасных значений в коде нет. Если записи нет, плагин при старте не запускается (подробности в журнале). Так ошибка разработчика видна сразу.

Загрузка. Нет файла - берутся умолчания. Файл поврежден или не читается - умолчания и сообщение пользователю, а сам файл не перезаписывается: пользователь исправляет или удаляет его, иначе старые настройки пропали бы бесследно. Запись одной категории неверна (неизвестный тип порядка, разрядность вне диапазона 1-9, старый формат) - заменяется только она, на запись по умолчанию, остальные категории остаются, пользователь получает сообщение.

Сохранение - файл пишется целиком, при успешной записи номеров и при закрытии окна, отдельную кнопку сохранения не делал: так настройки не теряются, если пользователь про нее забыл. Сбой записи - сообщение пользователю, подробности в журнале.

`Newtonsoft.json` не пользуюсь, для полноценный работы с настройками, достаточно добавить экспорт\импорт. При большом количестве категорий, стратегий порядка - добавить конфигуратор.

## 5. Как проверяли

Модульные тесты без Revit: 51 тест Core и 34 теста UI, на net48 и net8.0. Покрыты:

- расчет номеров: счетчик по уровням, пропуск занятых, стадии помещений, ошибки уровней, повторяемость;
- все 8 вариантов обхода сетки 3x3, допуск ряда, координаты ближе 1 мм;
- шаблон и разрядность;
- файл настроек: чтение, поврежденный файл, неверная запись, старый формат, встроенные умолчания;
- защита записи в координаторе: данные изменились, документ не активен или сменился, откат при отмене, перечитывание таблицы по событию отмены шага нумерации (событие от Revit подменено), охват "выбранные и найденные";
- поиск во всех режимах, наличие текста у каждого значения перечислений и у каждой категории, порядок сортировки статусов.

Сборка под Revit 2022, 2024 и 2025 проверена без ошибок и предупреждений.

### Проверка в Revit (ручное + mcp):

- Тестовая модель A (test-A.rvt): 7 уровней, около 60 дверей, 11 окон, 49 стен, 15 помещений. Подобраны пограничные случаи: сетка 3x3, "лесенка", двери ближе 1 мм, часть здания под 30 градусов, дуговая, составная и витражная стены, группы, сборка, вложенные семейства, снесенная дверь, помещения в двух стадиях, неразмещенное, неокруженное и избыточное помещения.

## 6. Известные ограничения

### Нумерация и сравнение значений

1. Значения сравниваются точно, с учетом регистра, но после обрезки пробелов по краям. Номер "д-1-001" вне охвата не занимает "Д-1-001". Значение с пробелами по краям ("Д-1-001 ") считается совпавшим с новым и не перезаписывается.
3. Занимают номера только элементы, которые плагин читает. Составные стены, семейства "в контексте" и элементы второстепенных вариантов конструкции не читаются, их номера не заняты, повторы с ними возможны.
4. Элемент, занятый другим пользователем, но находящийся вне охвата, в таблице показан как "Вне охвата", а не "Зафиксирован" (причина фиксации определяется только для элементов охвата), хотя его номер учитывается.

### Порядок

5. Порядок использует только X и Y точки элемента, высота (Z) не учитывается: два элемента на одном уровне в одной точке в плане, но на разной высоте различаются только по ID.
6. Точка стены - середина линии расположения (у дуги по параметру кривой, а не по хорде), у помещений - центр габарита: у Г-образного помещения он может лежать вне помещения.
7. Опорный элемент ряда - первый элемент охвата в этом ряду. Состав рядов, а значит и номера, зависят от охвата: если убрать из охвата первый элемент ряда, опорным станет следующий, и ряды могут разбиться иначе.

### Шаблон и проверки

10. Если уровень не входит в шаблон, охват должен быть на одном уровне. Элементы без уровня считаются отдельной группой, поэтому их смесь с любым уровнем тоже блокирует запись.
11. Предупреждение "номер длиннее разрядности" не показывается при разрядности 1.
12. Совпадение новых номеров проверяется только среди элементов охвата. Совпадение с элементами вне охвата снимается пропуском номера, а не ошибкой.

### Запись

13. На время записи снимаются все предупреждения Revit, а не только о повторяющемся значении: они удаляются молча, откатывается только транзакция с ошибкой.
14. Запись пропускается целиком, если расходится статус или новое значение хотя бы у одного элемента, и тоже если изменилось число элементов в категории. Добавление или удаление любого элемента между расчетом и записью требует нажать "Применить" заново.

### Окно и вызовы Revit

19. Если Revit отказал в вызове, окно молча остается как есть, запись о отказе только в журнале.
20. Выбор в модели сбрасывается при смене документа. Во время выбора окно скрыто и возвращается по завершении вызова.
21. Окно перечитывает категорию при каждом переключении категории и при "Обновить": кэша нет.

### Настройки и журнал

22. Настройки сохраняются при успешной записи и закрытии окна. Если Revit завершится аварийно, изменения настроек с последнего сохранения пропадут.
23. Запись настроек не атомарна, в настройки попадают только зарегистрированные категории (запись неизвестной категории из файла при следующем сохранении исчезнет).
24. Журнал: один файл в день, хранится 14 дней. При сбое записи строки журнала теряются без сообщения; две копии Revit одной версии пишут в один файл.

## 7. Как использовался ИИ-ассистент

Работа велась с Claude Code. Разбита была на этапы формирования функциональных требований (человек), тз (человек + ии), написание кода (ии), ревью (человек + ии), тесты (человек + ии), README (человек + ии).

Я определял архитектуру, описывал ключевую структуру классов и взаимосвязь. Т.к. проект не сложный, специфических багов и отладки с моей стороны не требовалось, код писал полностью через агента. Ревью проводил так же с агентом, большинство моих замечаний шли на упрощения реализации, удаление избыточного кода. Часть тестов запускал через MCP в Revit, часть тестов выполнял вручную. Работа с гит велась тоже через агента.
